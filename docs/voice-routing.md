# Voice routing

Both dictation and command mode route saved voice shortcuts through the same bounded matcher. Exact triggers rank before filler-stripped triggers, then fuzzy matches with normalized Levenshtein similarity at least 0.75. Longer matched aliases rank first within a tier; custom shortcuts win equal-length ties against built-ins. Unicode word boundaries prevent exact prefix matches inside longer words. Built-in speech aliases are derived from canonical triggers, so saved profiles gain aliases without resetting enabled preferences.

Custom shortcuts can share a trigger with a built-in. Duplicate custom triggers remain rejected. Command mode tries saved shortcuts first; a recognized disabled or invalid shortcut family cannot reopen through the independent command parser. Independent syntax such as `launch Calculator` and `search for weather` remains available.

Website targets accept validated HTTP(S) URLs and bare hostnames, spoken `dot`, surrounding quotation marks and trailing sentence punctuation. Explicit navigation also supports validated `mailto:` links, including optional recipients and encoded CRLF body lines under RFC 6068. Header line breaks and malformed addresses remain unresolved; opening a link delegates composition to the mail client and never sends mail. Custom website actions accept HTTP(S), and credentials and empty/invalid addresses remain unresolved. Custom `{{text}}` substitutions are URI encoded. Common folders accept singular/plural names and optional `the`/`folder`, including Applications. OS folder-opening failures are surfaced rather than reported as success.

The matcher bounds input length, trigger length and candidate count. Unit and mocked main-action tests verify routing and failure behavior without opening apps or websites. Physical microphone, shortcut and insertion acceptance still requires granted OS permissions.

Custom shortcuts now support ordered lists of websites, applications and folders. Website actions select a browser and profile from read-only discovery, or the system default browser. Chromium groups use one new window, Firefox groups use a new window and subsequent new tabs; native runtime behavior still needs verification. Applications optionally receive a folder, and folder actions can contain multiple paths. Legacy simple shortcuts derive an action plan without changing saved data. Planning validates all actions before any launch; execution stops on an OS failure. Store saves and backup restores validate the new schema atomically.

The browser catalogue detects an exact allowlist of Mac app bundles and native executables, including Apple’s Safari Cryptex path. Chromium profiles use only display metadata from `Local State`; Gecko profiles use `profiles.ini`; returned data contains browser/profile names and selector IDs, never login data. Metadata reads are size-bounded, profile counts are capped, and unsafe relative paths/symlinks are rejected. No profile files are copied. The editor preserves unavailable selections and unsaved text across asynchronous discovery; changing a browser explicitly resets its profile.

Missing browsers, removed profiles and immediate launch failures fall back to the system browser. Browser process dispatch alone does not prove a window loaded; late failures after the short launch check cannot be observed by this mechanism. Tests use synthetic metadata and mocked effects. Live browser/profile/window acceptance and vendor path compatibility remain incomplete.

The packaged ordered-action revision was tested through its real editor: two temporary folder paths and Finder’s optional folder survived reordering and saving. Running the saved alias with a leading `please` opened Finder windows for the parent fixture folder and both child folders. The saved fixture was disabled afterward. This verifies that bounded application/folder sequence, not live speech or browser groups.

Behavior evidence: [official workflow documentation](https://docs.vowen.ai/features/workflows), checked October 7, 2026, and [RFC 6068](https://www.rfc-editor.org/rfc/rfc6068.html), sections 2 and 5. Original implementation and tests were authored independently.
