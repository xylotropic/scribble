# Memory references

Scribble indexes named notes and user-selected files through the configured AI provider. Successful summaries, with their names, become context for Command Mode and non-polish AI utilities. Pending, interrupted and failed items do not contribute context. Dictation enhancement and meeting summaries do not use Memory. Raw extracted text stays available locally for reindexing; command context uses summaries.

File imports are copied into the workspace’s private `memory-files` directory with random names and owner-only permissions. Moving or deleting the original does not affect an imported reference. Deletion removes only a managed copy, and replacement removes the previous copy only when no other item references it. Failed saves and canceled copies remove new partial copies. Existing legacy references are not silently copied or deleted.

On relaunch, persisted summaries and error states hydrate without reading source files or calling a provider. Interrupted indexing becomes `needs-index`, so the user can retry. Reindex uses the stored copy. Provider identity comes from the settings snapshot that made the request, even if the user changes providers while it runs. Deletion aborts an in-flight request and prevents late results from recreating the item.

UTF-8 TXT, Markdown, JSON, CSV, YAML, TOML, XML and HTML/HTM files are read as literal reference text. Markup and scripts are not executed. DOCX uses bounded local text extraction; it is not uploaded as a native Gemini DOCX document. The DOCX extractor validates its package and XML, limits decompression and forbids external entities. Files are capped at 8 MiB; extracted text at 500,000 characters. Symbolic-link inputs are rejected.

For Gemini and Anthropic, PDF indexing validates the file and sends the original PDF bytes in one explicit summary request. This supports scanned PDFs without local OCR. Encrypted, malformed or oversized PDFs fail before upload. Gemini permits at most 1,000 pages; Anthropic at most 100, with the app’s 8 MiB bound applying to both. Model and account limits may be narrower. The provider receives the complete attached PDF, and its normal usage charges apply. See the official [Gemini document processing](https://ai.google.dev/gemini-api/docs/document-processing) and [Anthropic PDF support](https://platform.claude.com/docs/en/build-with-claude/pdf-support) documentation.

Other providers use local PDF text extraction through `pdfjs-dist`, with code evaluation disabled, a 300-page/30-second bound, and no OCR. Scanned PDFs without searchable text produce an explicit error. Text summaries use messages of at most 12,000 characters and bounded hierarchical combination. Empty, oversized or malformed replies and provider failures become errors; no alternate provider is called silently.

The underlying `MemoryIndex` retains a bounded local lexical search API, but lexical search is not used to select command background context. The [public Vowen Memory documentation](https://docs.vowen.ai/features/memory) establishes file-copy, provider-summary and indexed-only context behavior. Scribble’s local DOCX extraction and provider-independent text-PDF fallback are original implementations with the differences described above.

Verification uses real text/PDF/DOCX fixtures and mocked provider calls: exact 8 MiB copy, source move/deletion, safe replacement/deletion, canceled indexing, summary hydration, provider snapshot changes, scanned PDF attachment, encryption/page bounds and provider errors. No cloud inference or model accuracy claim is established by these tests.
