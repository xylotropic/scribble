## Current source trace

- `src/main/index.js:650` onward captures an insertion target before utility input and AI processing. Successful utility results are retained privately, then `show()` opens/focuses the main workspace (`index.js:131`), and `utility-result` selects its AI page (`src/renderer/app.js:2677`). This is a workspace panel, not an independent floating banner.
- Command results are retained by `attachCommandReview` (`index.js:806` onward), with private target/context/images and bounded expiry. `command-result` changes the renderer to its Command page (`app.js:2678`). Voice results emit from transcription completion (`index.js:1370`); that emission does not itself establish an independently visible banner when the workspace is hidden.
- Command and utility panels render selectable text or sanitized Markdown (`app.js:636`, `:716`). Explicit Copy copies the complete original text. Browser text selection supports ordinary selected-copy behavior; there is no custom Cmd+C handler establishing the exact no-selection clipboard contract in a dedicated banner. Preview navigation is mediated rather than allowing workspace navigation.
- Insert uses opaque review IDs, never renderer-supplied text. Native target-token validation protects the original field; insertion can fail safely if ownership changes (`index.js:823` onward). Utility reviews use the corresponding retained utility result. Tab is handled only when the result element itself has focus (`app.js:2586`, `:2594` onward). Result arrival does not focus that element automatically.
- Escape clears a command or utility panel and dismisses its backend review (`app.js:2584` onward). An earlier global busy-recording/processing branch cancels work first. Source does not establish a versioned banner's two-stage cancel/refinement restoration behavior.
- Typed refinement forwards current result text, history ID and review ID (`app.js:2114`). Main reuses private images, captured context, original target and automatic context (`index.js:2040` onward). History revisions are capped at 30 (`index.js:2081`). The history page has a revision pager (`app.js:584` onward); the live result panel does not.

## Concrete missing behaviors

1. **Separate persistent floating review surface.** Neither the recording overlay nor native indicator supplies selectable AI output, review actions and refinement states. Main workspace focus is currently required for utility review; command result visibility depends on the workspace. A banner should appear above the working app without navigation to an application settings page.
2. **Immediate result interaction.** Tab currently requires manually focusing the result element. A focused banner should support Tab for its displayed version, Escape and an explicit Copy button while keeping selected Cmd+C confined to selected result text. Clipboard behavior with no selected text needs a focused renderer test and eventual desktop proof.
3. **Voice refinement of the retained review.** The documented repeat-command-shortcut action must route to the active review rather than capture a new selection/screen. Current typed review reuse is useful infrastructure, but a new voice activation is not evidence of review-aware follow-up routing. The banner needs a localized shortcut hint plus listening/thinking states.
4. **Live version pager and cancellation restoration.** History paging does not let Tab insert a chosen earlier live reply. A review session should retain bounded versions, expose an active version ID, and cancel a follow-up back to its preceding visible reply; a subsequent Escape dismisses. Refinement context should use the original request and latest reply, independent of the version currently being viewed. The current writing prompt uses the new instruction and provided previous text; original-request inclusion needs explicit implementation.
5. **Failure retry surface.** Errors currently surface through notices/toasts and failed history rows. There is no visible alternate-provider chip row retaining the failed utility/command's input snapshot and retrying it while updating the configured default. This is separate from ordinary provider Settings controls.

## Proposed original architecture

Add a dedicated bounded Electron review window with a separate renderer and restrictive preload. Keep existing native insertion tokens and all selected text/files/images solely in a main-process review-session store. Public IPC payloads should contain session/version IDs, display text/preview, insertion availability, status, shortcut hint and configured retry-provider labels only. Do not expose targets or recapture context from the review renderer.

A session owns its request snapshot, current provider configuration, bounded versions, selected version, failure metadata, expiry and one cancellable refinement job. Actions validate the current session/version before copy, insertion, dismissal, retry or refinement. The native command-hotkey path can detect an active review and start a follow-up recording against that same session. Late results must never replace a newer or dismissed session. Tool results terminate refinement review as documented. Closing the banner cleans up retained images/jobs/tokens without deleting the history entry.

Use the existing Markdown sanitizer for display, plaintext for copy/insertion, and existing target activation/field verification for paste. Offer only actually configured alternate providers; retry uses private captured input, checks current availability, and changes the default only through the validated settings path. Placement can reuse active-display geometry logic, with an independently focusable review surface rather than changing the nonfocusable recording indicator.

Required tests include hidden-workspace result visibility via window fakes; version-specific insertion; selected versus empty Cmd+C; Tab focus; stale-session actions; follow-up context reuse and cancellation restoration; capped versions; provider retry snapshot/default changes; keyboard hint updates; escaped/localized labels; Markdown link mediation; expiry and shutdown cleanup. Live macOS focus, selection, keyboard handling and insertion remain unverified until authorized desktop acceptance.
