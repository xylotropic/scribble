# FFmpeg runtime provenance and distribution

The npm @ffmpeg-installer/darwin-arm64 4.1.5 binary reports FFmpeg 4.4 configured with `--enable-gpl --enable-version3 --enable-nonfree`. It must not be distributed in Scribble. The FFmpeg project's [license guidance](https://ffmpeg.org/legal.html) identifies nonfree builds as nonredistributable. The installer is not an acceptable release runtime.

`scripts/setup-ffmpeg.mjs` builds a replacement from pinned upstream source. Configuration explicitly enables GPL, disables nonfree and autodetection, statically links x264, libvpx, Opus and LAME, and uses built-in AAC and PCM encoders. It does not link this executable into the Electron program. Scribble invokes it as a separate command-line process. FFmpeg's own GPL notices and corresponding-source obligations still apply to distribution of the executable.

The exact URLs, source versions/commit, archive names and SHA256 are in [ffmpeg-sources.json](ffmpeg-sources.json). Downloads came from upstream FFmpeg, VideoLAN, Xiph, WebM's official GitHub mirror, LAME's official SourceForge distribution, and pkgconf. Hashes pin and verify the exact downloaded bytes on every build. Upstream detached OpenPGP signatures were not verified because GPG was unavailable; SHA256 checks do not establish a signing-key authenticity claim. No upstream source was modified.

Build recipe: macOS arm64 or Intel x64 with Apple clang/make/tar; only arm64 has been compiled and exercised. Intel selects libvpx x86_64-darwin25-gcc and disables libvpx assembly/FFmpeg x86 assembly when nasm is unavailable. no Homebrew or system package changes. A private user-local prefix holds static dependencies and pkgconf. The installed SDK27 exposes architectures unsupported by this host linker, so SDK selection prefers explicit SCRIBBLE_MACOS_SDK, then installed SDK26.5 if present, then xcrun --show-sdk-path. It targets macOS13. SCRIBBLE_FFMPEG_BUILD_DIR can select another space-free build directory. Run `node scripts/setup-ffmpeg.mjs --plan` to inspect, or omit --plan to compile. A private build PATH wrapper makes libvpx use that same SDK without patching upstream code or changing system defaults. The recipe disables x264 assembly to avoid additional assembler tooling; this sacrifices some encode performance.

Successful builds stage `release/runtime/ffmpeg` and `release/runtime/licenses/ffmpeg/`: upstream license/patent notices, all exact source archives (including static codec dependencies), source manifest, recipe JSON, and the installer script. Keep this entire directory alongside the executable in the distributed application, and make it accessible to recipients; do not remove archives to reduce app size. The manifest and recipe allow reconstruction without the original developer's machine. The included setup script finds the colocated manifest when run outside the repository; it stages standalone rebuild output under its user-local build directory. SCRIBBLE_FFMPEG_STAGE_DIR explicitly selects the staging directory (legacy SCRIBBLE_FFMPEG_OUTPUT_DIR is also accepted). --package-root DIR selects a source/project root and its default release/runtime staging location. The script falls back to a colocated source manifest when invoked from bundled licenses. Do not claim rebuilt-byte reproducibility merely because the recipe is supplied.

Build readiness is not codec verification. Before packaging, run the staged binary's -version/-buildconf/-encoders and otool -L; reject nonfree configurations and non-system dynamic dependencies. Verify real fixture conversions for libx264 MP4, libvpx-vp9/libopus WebM, libmp3lame MP3, libopus audio, AAC M4A, PCM WAV and image conversion. Record actual evidence after compilation rather than assuming configure success. No user media or cloud service is required for those synthetic fixture checks.

Verified build on October 7, 2026: FFmpeg8.0.3 SHA256 `73a12bbd32ab45cfbb705ff94bf8f1e36d2caa7a0c3d1a39e1e1230897d06157`. Configuration contains --enable-gpl, --disable-nonfree, all four requested external codecs and explicit system zlib (PNG support). otool reports only Apple system libraries/frameworks. Eight synthetic encode/decode fixtures passed: H264/AAC MP4, VP9/Opus WebM, MP3, Opus, AAC M4A, PCM WAV, PNG and JPEG. Evidence with exact commands/streams is in [ffmpeg-verification.json](ffmpeg-verification.json). This proves those short fixture operations, not arbitrary media performance or exhaustive codec correctness.

The local `release/runtime/ffmpeg-build.json` cache marker records architecture/platform, binary SHA256, current setup recipe SHA256, recorded build-recipe SHA256 and every source archive SHA256. Packaging should verify all marker values against actual bytes before reusing a staged runtime; presence alone is insufficient. The verified arm64 binary was retained when SDK fallback, the untested Intel branch and cache/staging metadata were added, because arm64 configure flags remained identical. The marker states that provenance explicitly; it does not claim the new script was rerun as an Intel build.
