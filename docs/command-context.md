# User-selected command file context

`src/main/command-context.js` provides `prepareCommandFiles(paths,{signal})` and `LIMITS`. It reads only the exact absolute paths supplied by the file chooser. It never discovers files, scans directories, watches folders, reads credentials, captures the screen or calls a model. Root main owns the file dialog, per-command lifetime, screen capture and the decision to send content to a selected local or cloud model.

Returns `{text, images, sources}`. Text/configuration and extracted PDF text are encoded as named JSON lines under a context instruction. This preserves filenames/content as data and prevents filenames from creating extra instruction delimiters. It does not guarantee model resistance to prompt injection inside file content. Sources record selected path, basename, input bytes, type and extraction details. Images use the existing cloud schema `{mimeType,data}` with base64 data; all accepted images become bounded WebP. Source imageIndex associates names with image array entries. Root should show those selected names to the user before running a command and never persist files or capture unrelated context automatically.

Accepted text: txt, md, markdown, csv, json, yaml/yml, toml, xml, html, css, js, ts, py, sh, ini, log. UTF-8 required; invalid encoding/NUL binary content rejected. Configuration text is evidence, not executed or loaded as app configuration. PDFs use the already installed pdfjs-dist parser, disable JavaScript evaluation/font loading and extract text without OCR. Scanned/no-text PDFs return an explicit error. PNG, JPEG and WebP use Sharp to decode and verify their actual format; dimensions are bounded to 1536 pixels, oriented automatically, and re-encoded at quality80. Animated inputs use a single frame; this is not video support. No proprietary assets were copied; tests generated original simple fixture images and a PDF sentence.

Limits: 10 files, 5 images, 8MiB per file, 24MiB total input, 60,000 total extracted text characters, 100 PDF pages, 30-second PDF parsing timeout, 40 million input image pixels and 3MiB per converted image. Images are progressively downscaled when required. No silent text truncation: exceeding a limit fails the operation. Individual PDF pages currently use getTextContent; very dense pages may allocate a larger temporary array before the character cap is applied. Cancellation is checked between files/pages and destroys an active PDF task; a running Sharp decode cannot be interrupted mid-call, but its result is discarded on cancellation.

Only regular files allowed; directories, symlinks, duplicates, relative paths and unsupported extensions fail. Files are checked before opening and by device/inode/size after opening; actual read size is checked again. This reduces file replacement races without claiming an immutable snapshot of a concurrently edited file.

Six tests pass, including real PDF text extraction, actual PNG/JPEG/WebP decode/resize roundtrips, named configuration evidence, format mismatch, malformed UTF-8, symlinks/folders/duplicates, limits and cancellation. The standard-font PDF fixture emitted pdfjs's standardFontDataUrl warning while successfully extracting its expected sentence; font configuration in packaged execution needs independent evidence. No live model or screen-capture behavior is claimed by these parser tests. Native document uploads remain separate: these files become text/image context rather than provider Files API resources.

Screen context can be cropped before attachment using left, top, width and height percentages within the selected preview. Cropping validates the rectangle and creates a PNG containing only its pixels; it does not attach the full image alongside the crop. The preview resolution is the screen-context capture resolution, not a claim of full native display resolution. A real two-color image test verifies that the selected half contains none of the excluded half’s pixels. Actual screen permission and live vision inference remain unverified.
