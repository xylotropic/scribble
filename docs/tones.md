# Original tone selection

October 7, 2026. Private static evidence from installed Vowen 0.5.9 contains tone fields `id`, `name`, `icon`, `isDefault`, `speechEngine`, `speechModel`, `aiEnhancement`, `languageModel` (provider/model), `customInstructions`, `apps`, `websites`, `shortcut`, plus spoken language and enabled controls. Its settings strings describe automatic app/site activation, tone-specific model/language overrides and a shortcut that dictates with that tone. The main bundle contains both automatic `resolveTone` and explicit `resolveToneById`, and indicator state distinguishes pinned and resolved tones. These are factual observations, not copied implementation. Raw evidence remains private and excluded from Git.

Automatic resolution's visible branches prioritize a matching website before a matching application. Exact obfuscated matching semantics and every pin/hotkey interaction were not proven by runtime tests. Default migration evidence shows a Default tone with global-derived configuration; this alone does not prove all historical default fallback behavior. The [public feature inventory](public-features.md) records the free one-tone limit; Scribble's original implementation does not reproduce an artificial subscription cap.

`src/main/tones.js` exports `resolveTone`, `applyTone`, `pinTone`, `resetTone`, `validateTone`, `enabled`, `normalizeSite`, `siteMatch`, `shortcutConflicts`. Root owns native context acquisition, persistence, recording hotkeys and UI.

The independently designed policy is explicit: invocation hotkey tone, then manual session pin, then website (longest path wins), then application (first configured match), then selected default / enabled isDefault tone, then global settings. Disabled or missing IDs never block fallback. A reset clears only the pin, preserving default preference. Matching uses exact hostname after dropping www, exact path or slash-boundary descendant; it rejects hostile hostname suffixes and path-prefix collisions. Subdomains need explicit rules. This deterministic rule is an implementation choice rather than a claim that all original matching behavior is identical.

Context fields: `app` stable app identifier, `url` verified browser URL, `hotkeyToneId` invocation ID. Selection fields: `pinnedToneId`, `defaultToneId`. `resolveTone` returns a cloned tone and reason (`hotkey`, `manual`, `website`, `app`, `default`, `global`). Caller may render the reason to explain selection. It must pass only actual discovered browser URL, not window title guesses.

`applyTone` clones global settings for the current recording. Speech engine/model map to Scribble `speechProvider`/`modelId`; language maps to `language`, AI enhancement to `aiEnhance`, language model to `aiProvider`/`aiModel`, and custom writing instruction to `toneInstructions`. Null or empty speech overrides inherit globals; explicit false enhancement remains false. Root must compose toneInstructions into its AI prompt and resolve cloud speech engine/model selections as appropriate; merely calling this pure function does not wire those capabilities. Global settings are never permanently rewritten by context activation.

Six tests prove the specified selection order, path/hostname boundaries, disabled/deleted fallback, ephemeral overrides, reset preservation, cloning, validation and canonical shortcut modifier conflicts. Native foreground context, website discovery, actual hotkey invocation, provider selection and manual pin UI require separate runtime evidence before parity claims. Shortcut conflicts here compare tone bindings; root must additionally check global recording shortcuts.
